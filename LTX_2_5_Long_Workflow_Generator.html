LTX-2.5 Long Workflow Generator T2V

Browser-based • API optional • Same planner + last-frame chaining as MiniMax H3, expanded from the official LTX-2.5 two-stage T2V graph

1. Prompt & Duration

Trims 8 frames (~0.33 s) after the locked first frame on later clips.

Live calc: ≈ 6 clips  ·  LTX frame count is 8n+1 (official: duration × fps + 1).

2. LLM Provider (optional)

Keys stay in localStorage. Browser CORS may block some cloud providers — Ollama works best for local use.

3. Mode & Workflow Settings

Official distilled template uses 1280×720 @ 24 fps. Latents are generated at half res then spatially upsampled ×2.

Advanced model names & distilled sigmas

Distilled LTX-2.5 uses CFG 1 + the official ManualSigmas lists. Full (non-distilled) models typically want higher CFG.

4. Segments (editable)

Paste planner JSON, edit by hand, generate locally, or let an LLM create it. Continuity language is injected on non-first segments. First segment is pure T2V when that mode is selected; later segments lock the previous last frame via LTXVImgToVideoInplace + LTXVAddGuide.

How this maps to official LTX-2.5 T2V

  • Shared stack matches video_ltx2_5_t2v.json: distilled transformer, Gemma 4 CLIP, video + audio VAEs, latent ×2 upsampler, dual CFG guiders, two-stage sampling (low-res then high-res).
  • Chaining is the MiniMax pattern: last decoded frame of clip N becomes the first-frame guide of clip N+1. After the lock, a settle window (1 LTX step = 8 frames by default) is dropped and audio is re-muxed to the kept pictures.
  • T2V first clip uses empty latents only. I2V first clip (and every later clip) injects the image at half-res with LTXVImgToVideoInplace, then again after upscale with LTXVAddGuide at frame 0, strength 1.
  • Do not wrap this in the official subgraph. Subgraphs hide the last-frame wire. The generator emits a flat graph you can queue as-is.
  • 5 s clips match the official default duration. Shorter clips = more joins. 8–10 s is a better continuity/speed compromise for long pieces.
